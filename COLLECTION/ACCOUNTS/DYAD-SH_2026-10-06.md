### 2. Independent shell security review
Relevant file:
- `src/prompts/shell_review_policy.ts`

Observed patterns:
- separate reviewer that never executes the command;
- JSON allow/ask/block decision;
- authorization is distinct from safety;
- dedicated-tool preference;
- explicit consequential-action approval;
- hard blocks for credential theft, bypasses, detached jobs, privilege escalation and opaque destructive effects;
- prompt-injection-resistant treatment of repository/user/tool text as untrusted evidence.

Reuse decision: **UPGRADE candidate** for existing permission-aware executor / action-approval / evidence-backed operator Skills.

## Important architectural observation

Dyad is more valuable to us as a **source of engineering patterns** than as a project to fork wholesale.

Its strongest overlap with our current architecture is:
`tool capability → authorization/safety review → typed execution → evidence/testing → deployment`

That maps naturally into existing canonical Skills instead of creating a parallel Dyad-specific Skill family.
