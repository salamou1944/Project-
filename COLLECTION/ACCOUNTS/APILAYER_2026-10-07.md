## High-value reusable patterns observed

1. Evidence-backed verdicts: findings should expose the evidence and contribution to the final score/verdict.
2. Graceful degradation: missing/exhausted provider keys should degrade only the affected surface where possible rather than falsely reporting success.
3. Quota-aware execution: deduplicate inputs before consuming API credits and use bounded concurrency.
4. Server-side credential isolation: API keys remain behind server routes and are never exposed to the browser.
5. Multi-provider composition: compose specialized APIs behind a single application workflow while keeping provider boundaries explicit.
6. Honest comparison: normalize units/periods before comparison and refuse ambiguous comparisons rather than inventing a result.
7. Cached fallback: serve cached/neutral results when upstream providers are temporarily unavailable, with the degraded state made explicit.
8. Runtime traceability: developer-facing API tools can expose request/response traces without exposing credentials.
9. Source-backed scoring: every weighted signal should map to a named evidence item rather than an opaque score.
